# 改写保真与真实检测：第二轮设计

用户要求继续推进核心目标：中文优先，修改 AI 初稿的表达而不改变科研内容，并取得真实检测前后对照。用户此前已明确委托设计、研发、测试和公开发布，不再逐项确认。本轮不扩展新 UI，也不把原文保留率或通过单元测试当作效果。

## 选择与边界

三个候选方向是扩大规则、引入语义裁判、重新训练。当前已知错误有直接可复现的词面原因，训练语料授权和独立人工标签不足，因此先做有负例约束的小范围规则修复及生成侧对照。暂不让第二个小模型充当自动放行裁判，也不把整篇拆成互不关联的句子。

1. 数量：补常见中文量词及边界明确的英文文字整数；只在明确数量结构中统一支持的整数记法。保留单位、百分比/千分比、正负、区间及小数精度。不得把 3名 与 3组 混同，不放宽用户要求原样保留的术语，不全局合并否定词。
2. 许可、要求和来源：对“可以→必须/省略”“需要→已经”“引文占位/虚构来源声明丢失”分别发出警告。候选仍由既有任何警告均保留原文的策略处理。这是有限词面风险检查，不是完整命题对齐或语义等价证明；同词移到别的主体仍可能漏检。
3. 生成输入：固定 4 个已知案例、两个种子，对照 JSON 转义正文与原样文本正文；另外单独检查 presence penalty。原始请求响应完整保留。只采用有具体保真收益且回归通过的变更，不能凭几例宣称质量普遍改善。

## 评测先定规则

- 所有旧开发样例和原始报告不覆盖；离线重放旧候选，逐项列出放行/拦截决策变化，不借新随机输出掩盖规则回归。
- 真实模型两套既有语料均完整重跑，保留所有候选、失败和未改写文本。保持 requires_review=true。
- 外部公开网页试测预先选择 v0.1.0 的 prose 发布报告：六段中文按原顺序以两个换行连接成一份中文测试文，四段英文同样形成一份英文测试文。每种语言分别比较合成原文与软件最终稿，未改段落也保留。每份合成文只是一个观测，不将段落数当作独立检测次数。先中文再英文，先原文再改写。
- 仅提交项目已公开、CC0、虚构的合成材料到官方可见免费入口。不得上传私人论文、创建账户、购买额度、绕过验证码或切换身份绕限额。记录所有失败；若中文入口明确不支持或要求登录/付费，说明具体阻碍。
- 有实际分数才写分数；记录 UTC 时间、可见检测名称、版本未知状态、精确文本 SHA256、原始可见结果和截图。单个平台的小样本结果不是中文学术场景普遍通过率，不是人类写作证明。
- 社区模型仅可作为另列的研究基线，不能冒充同名商业检测器；未有充分来源/校准验证时不作为产品验收门槛。

## 验收与发布

先失败测试，再实现，再运行完整后端与前端测试、构建、依赖审计和独立审查。中文与英文保持共享代码一致。成功的工程修复、真实模型质量观察、外部检测结果分开报告；核心目标不满足时仍保持预览版定位。
